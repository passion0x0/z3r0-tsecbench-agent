# AI 攻防全链路自动化 Agent —— 技术报告

> 作品名称：Z3r0-TSecBench 攻防自动化 Agent
> 赛道方向：漏洞自动化挖掘 / 二进制漏洞自动化分析（TSecBench 全类别攻防基准）

## 摘要

- **一句话**：把资深白帽的攻防方法论沉淀为可复用知识资产，驱动大模型无人值守地打完一整套攻防基准。
- **一个结果**：**同一个模型、同一个平台，成绩从约 6500 分做到 18300 / 23000 分**（54/63 题，79.7% 完成率），全程 0 人工介入。
- **一个结论**：制约大模型攻防成绩的第一瓶颈，**不是模型推理能力，而是"方法论 + 知识组织"**——这也是本作品全部工作的出发点。

| 关键指标 | 数值 |
|---|---|
| TSecBench 总分 | **18300 / 23000** |
| 题目完成率 | 54 / 63（79.7%） |
| 人机验证时间占比 | ≈ 0（无人值守） |
| 部署形态 | 单容器、离线、< 3GB |

## 一、作品概述

### 1.1 基座与原创性声明

本作品**基于开源黑盒红队平台 Z3r0（yv1ing/Z3r0）进行深度定制与二次开发**，特此声明。原版 Z3r0 提供了多 Agent 协作框架与基础工具手册；但直接使用原版跑 TSecBench 仅约 6500 分。

本作品的核心贡献是在该框架上做了**四大增量改造**，把成绩推到 18300 分：

| 层面 | Z3r0 原版 | 本作品增量 |
|---|---|---|
| Skill 体系 | 25 个工具手册（教"怎么用 nmap"） | **+70 个方法论 / CVE 专项**（教"怎么解题"） |
| 知识库 | 无 | **12405 条离线 CVE 库 + grep 命中机制** |
| 编排策略 | 通用对话 | **题目级委派 + 弹性时间预算 + 防自毁约束** |
| 部署形态 | 多容器、依赖外网 | **单容器 < 3GB 离线化改造** |
| **实测成绩** | **~6500 分** | **18300 分（同模型同平台）** |

> 涨出来的 11800 分，全部来自上述增量——**这就是本作品的原创工作量与价值所在**。

### 1.2 系统定位

系统面向真实攻防任务，构建了一套 **多角色 Agent 协作 + 方法论 Skill 体系 + 离线 CVE 知识库** 三位一体的自动化漏洞挖掘与利用系统，由大模型在统一调度下自主完成 **"目标识别 → 漏洞发现 → 利用 → 提权/横向 → 提交验证"** 的全链路攻防。

核心命题：**用"赛点经验与方法论"（而非答案）提升大模型的攻防实战能力，瓶颈在策略与知识组织，而非模型推理硬实力。**

## 二、技术架构

系统采用三层架构，最终打包为**单容器（<3GB）离线运行**，适配托管式靶场"无外网、限时、限资源"的约束：

```
【调度层】 CSO 指挥官 Agent —— 选题 / 委派 / 提交 / 关闭
             └─ 题目级委派 ─▶ 5 类专家（渗透 / 逆向 / 审计 / 密码 / 情报）
                    │
【知识层】 95 个方法论 Skill  +  12405 条 CVE 知识库
             ├─ 题型 Playbook（云 / WAF / 沙箱 / 固件逆向…）
             ├─ 产品 CVE 速查（OA / AI 平台 / 中间件全家桶）
             └─ 离线漏洞库（AboutSecurity 详案 + nuclei 模板）
                    │
【执行层】 本地命令执行  +  安全工具链（无 docker 依赖）
             └─ 内嵌 PostgreSQL + 应用 + nmap / sqlmap / gdb …
```

- **调度层**：CSO 是指挥官（只负责选题、委派、提交、关闭），不直接执行命令；5 个专家 Agent（渗透 cpe、逆向 cre、审计 cae、密码 cce、情报 cie）各司其职，一个专家独立负责一道题的完整链路（侦察→利用→拿 flag→自提交），避免"主 Agent 逐步指挥"的昂贵往返。
- **知识层**：这是系统的核心竞争力（详见第三节）。
- **执行层**：命令在容器内本地执行（无外网、无 Docker daemon），通过进程组超时控制、内联输出等工程手段保证稳定性。

## 三、核心算法与方法

### 3.1 多角色 Agent 编排（题目级委派）

传统做法是"主 Agent 发指令 → 专家执行 → 回传再发下一条"，每个命令都消耗一轮完整 LLM 往返。本作品改为**题目级委派**：CSO 将"一道题"整体委派给一个专家，专家自主完成全部动作，最后只回传 ≤200 字的精简结果（`code|status|flag|vuln|next`）。实测命令数/派发从 18 提升到 33，CSO 自身命令从几十条降为 1 条，上下文占用大幅下降。

配套的调度策略是"**从易到难 + 弹性时间预算**"：各类题先试探 1 题、30~40 分钟看清哪些类好解后集中收割；低分题 10~15 分钟无进展即换、高分多 flag 题给 60~90 分钟；连续 15 分钟无新信息或 2~3 条思路卡死就搁置。同时用硬约束防止自毁行为（防误提交、多 flag 必须挖满、禁止高并发爆破打崩目标、到达时限立即收敛）。

### 3.2 方法论 Skill 体系（失败驱动 + 题型驱动）

系统的知识不是"答案"，而是**针对题型的可复用方法论**。Skill 的产出遵循两条闭环：

1. **失败驱动**：从每轮实战的"卡死题"反推缺口。例如逆向题 agent 能反出校验算法却推不出唯一 flag、退化成盲猜提交（单题 17 次提交全错）→ 提炼"逆向题必须本地自验证、禁止猜 flag、单题提交≤2 次"的方法论。
2. **成功驱动**：从"满分维度"反推通用 Playbook。例如云攻击 6/6 满分后，提炼出"云服务类型识别 → 攻击面映射（S3 弱 ACL / Lambda 配置泄露 / SSRF 打 IMDS / OAuth 流程）"的通用四步。

最终形成 **95 个 Skill**：25 个工具手册 + 13 个方法论 + 57 个 CVE/攻击专项（Web 框架、OA 全家桶、AI 平台、云、AD、后渗透、免杀、固件逆向等）。每个 Skill 严格保持"题型级"抽象——只写"图数据库服务 → Neo4j/HugeGraph → Gremlin RCE 类漏洞模式"，不写任何具体题号与答案，因此换题、换题库依然通用。

### 3.3 离线 CVE 知识库（12405 条）

靶场无外网，agent 无法实时查 CVE，这是"产品 CVE 类题"反复卡死的根因。本作品将漏洞知识**离线化**为三层知识库（约 21MB）：

- AboutSecurity 649 份详案（250+ 产品，含指纹、影响版本、利用步骤、payload）
- nuclei-templates 11667 个检测模板（CVE 2000–2026 全年代 + 默认口令 + 暴露面 + 错误配置）
- 88 份现成攻击 payload

配套 `cve-kb-lookup` Skill 指引 agent 用 `grep -rli 产品名` 命中详案后照文档打。实测效果显著：本地 AI 平台专题从"只解 3 题"提升到"9 题解 8 题（2000 分）"，其中 hard 题（ComfyUI CVE-2025-67303、1Panel 默认凭据）均靠查库命中秒解。

### 3.4 模型适配与工程稳定性

- **模型分层**：调度层用廉价模型、攻坚层用强模型；单模型场景固定 deepseek-v4-pro。
- **幻觉工具名修复**：模型会杜撰不存在的工具名（execute_socket_command 等），通过注册工具别名 + `tool_not_found_behavior=return_error_to_model` + DSML 流式补丁三层兜底，把子 Agent 因幻觉导致的硬失败清零。
- **thinking 模式关闭**：关闭推理模式，避免多轮工具调用时 reasoning_content 回传报错。

## 四、实验结果

### 4.1 TSecBench 官方基准（托管模式，6 小时限时，63 题）

| 指标 | 数值 |
|---|---|
| 总分 | **18300 / 23000** |
| 完成题目 | 54 / 63 |
| 完成率 | 79.7% |
| 捕获 Flag | 55 / 74 |
| 维度表现 | 云攻击 6/6、对抗规避 14/14（满分）；二进制 12/13；Web 16/18 |

### 4.2 迭代增益（同一模型、同一平台）

| 阶段 | 成绩 | 关键改动 |
|---|---|---|
| 初版（原版 Z3r0） | ~6500 分 | 无方法论、盲猜提交 |
| 方法论注入 | ~14600 分 | 多角色编排 + 方法论 Skill |
| 知识库 + Playbook | **18300 分** | 离线 CVE 库 + 题型 Playbook + 调度策略 |

### 4.3 量化指标（对照大赛评分维度）

- **漏洞发现率 / 完成率**：79.7%（54/63），其中 easy/medium 类近乎满分，证明"知识命中"型漏洞发现率可接近人工水平。
- **误报率**：所有提交前经本地自验证（逆向题喂回校验函数、Web 题验证 flag 归属），提交正确率高，规避了"盲猜 flag"导致的误报浪费。
- **单题平均时长**：easy 题分钟级（如云 S3 弱 ACL 约 2 分钟），medium/hard 题在时间预算内收敛，全轮 6 小时解 54 题。
- **大模型运行成本**：首轮全量约 6.1 亿 tokens（单强模型 deepseek-v4-pro）；通过题目级委派 + 报告瘦身 + 停止条件，较初版"逐步指挥"模式显著降低往返消耗。
- **人机验证时间比例**：全流程无人介入，6 小时限时内全程自主选题、解题、提交、收敛，人机验证时间占比 ≈ 0。

### 4.4 AI Agent vs 传统人工模式（效能对比）

| 对比维度 | 传统人工攻防 | 本 Agent | 效能提升 |
|---|---|---|---|
| 完成 54 题耗时 | 数人 · 数天 | **6 小时 · 单机自动** | 数量级压缩 |
| 人力投入 | 多名安全工程师全程盯守 | **0（无人值守）** | 人力→0 |
| 覆盖广度 | 受个人技术栈局限 | **9 大类全覆盖**（Web/pwn/逆向/云/AI/APT…） | 广度不受个人短板限制 |
| 知识获取 | 临时查资料、依赖经验 | **12405 条离线 CVE 库即时命中** | 无外网仍可"知即秒杀" |
| 一致性 | 状态/疲劳影响发挥 | **策略稳定、7×24 可复现** | 消除人为波动 |
| 边际成本 | 人天成本，难规模化 | **token 成本，可并行可复制** | 可规模化 |

> 结论：在标准化攻防任务上，本 Agent 已能以**接近人工的漏洞发现率**、**远低于人工的时间与人力成本**完成全链路作业，验证了 AI 在安全攻防中的实战效能。


## 五、创新点总结

1. **方法论即核心资产**：不依赖"背题/答案"，而是把白帽经验抽象为"题型级"可复用方法论，换题库依然有效——这是可持续提升成绩的根本路径。
2. **离线知识库替代联网检索**：在无外网靶场，用 12405 条本地 CVE 库 + grep 命中，解决"产品 CVE 类题知道就秒杀、不知道就卡死"的痛点。
3. **题目级委派 + 精简回传**：把"逐步指挥"改为"整题委派"，大幅降低 orchestrator 上下文膨胀与 LLM 往返，兼顾并发与成本。
4. **失败驱动 + 成功驱动的双闭环 Skill 迭代**：每轮实战后从卡死题与满分维度双向提炼，形成可持续进化的知识库。
5. **单容器离线化工程**：将含工具链 + 知识库 + 内嵌数据库的完整系统压缩到 <3GB 单容器，适配托管式靶场部署约束。

## 六、总结

本作品验证了一条清晰的技术路线：**在真实攻防基准中，制约大模型成绩的第一瓶颈不是模型推理能力，而是"攻防方法论 + 知识组织"**。通过多角色编排、题型级方法论 Skill、离线 CVE 知识库三者的结合，同一模型在 TSecBench 上从 6500 分提升至 18300 分。这套"方法论资产 + 编排框架"可迁移到 SRC 定向漏洞挖掘、二进制自动化分析等真实场景，具有明确的实战落地价值。
